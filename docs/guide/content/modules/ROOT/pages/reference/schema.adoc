This page lists every key of a conference profile, an event override, and a calibration example, as the code reads them at {cfp-version}.
xref:profiles/index.adoc[How profiles work] explains the concepts, xref:internals/store.adoc[Store files] shows the files, and xref:internals/rules.adoc[How rules and verdicts are computed] describes what each rule kind checks.
xref:profiles/new.adoc[Research a new conference] shows how `/cfp:profile` fills these keys for you.

A profile lives in `profiles/<profile>/profile.md`, an event in `profiles/<profile>/events/<event>.md`, and an example in `profiles/<profile>/examples/<id>.md`.
`profile write --from-json` and `event write --from-json` take the same keys as JSON.

In the tables, "Default" is the value the loader or the reader uses when the key is missing.
"Validated" says whether `profile validate` checks the key.

== Profile

[cols="2,2,2,2,5"]
|===
|Key |Type |Default |Validated |Used by

|`id`
|string
|the directory name
|no
|The loader always sets it from the directory name under `profiles/`.

|`name`
|string
|empty
|no
|`/cfp:profile show` and `profile list`.

|`platform`
|string
|empty
|no
|`/cfp:profile show` and `profile list`.
Free text: no code compares it with a fixed list.

|`approved`
|boolean
|`false`
|no
|`/cfp:draft` refuses an unapproved profile.
With an event, the merged form counts as approved only when both are.
`/cfp:init` sets it to `true` on the profiles it copies into the store.

|`seed_version`
|string (ISO date)
|empty
|no
|`profile seed-status` compares it with the shipped seed as a string.
Empty means a local profile that is not a copy of a seed.

|`sources`
|list of URLs
|`[]`
|no
|Carried into the merged form.

|`session_types`
|list of <<session-type,session types>>
|`[]`
|yes
|Drafting, the speaker rules, and the review packet.

|`submission_limit`
|integer or empty
|empty
|no
|Fallback limit of the `submission_limit` rule.

|`selection_limit`
|string
|empty
|no
|Carried into the merged form.

|`fields`
|list of <<field,fields>>
|`[]`
|yes
|Drafting, counts, the paste view, and the review packet, in list order.

|`rubric`
|<<rubric,rubric>>
|scale 5, pass average 4.0, minimum criterion 3.0, no criteria
|yes
|The committee review.

|`rules`
|list of <<rule,rules>>
|`[]`
|yes
|The pre-flight check.

|`rejection_reasons`
|list of strings
|`[]`
|no
|The committee reviewer lowers a criterion for each reason that applies.

|`bio_on_form`
|boolean
|`true`
|yes
|Only an explicit `false` switches the bio off.
Drafting then attaches no bio, the count reports `not-on-form`, and the review packet and the paste view carry no bio text.

|`bio_limit`
|integer or empty
|empty
|no
|The bio count.
It is coerced like a field `limit`.

|`bio_limit_status`
|<<limit-status,limit status>>
|`unverified`
|yes
|The status of the bio count.
|===

The loader turns a single value of `sources`, `session_types`, `fields`, `rules`, or `rejection_reasons` into a one-item list.
A `rubric` that is not a mapping is replaced with the default rubric.

=== Body sections

[cols="1,4"]
|===
|Section |Used by

|`## Drafting guidance`
|Free prose for drafting.
The committee review packet carries it.

|`## Notes`
|Conflicts and assumptions from the research.
|===

`profile write` adds both headings when they are missing.
In its JSON, the sections go into a `body` mapping with the heading as key, or into the keys `drafting_guidance` and `notes`.

== Field

[cols="2,2,2,2,5"]
|===
|Key |Type |Default |Validated |Used by

|`id`
|string
|none
|present and unique
|The proposal section `Field: <id>`.
An event override patches the entry with this id.

|`label`
|string
|the `id`
|no
|Counts, the paste view, and the review packet.

|`required`
|boolean
|`false`
|no
|A required field without text is listed in `missing_required` by the count, and the paste view warns about it.

|`kind`
|<<field-kind,field kind>>
|none (`profile validate` reports it); the paste view and the review packet read it as `text`
|yes
|`proposal set-field` and the drafting steps per kind.

|`limit`
|positive integer or empty
|empty (no limit)
|yes
|The character count.
The merged form coerces it: a whole number, also one written as a string such as `"75"`, counts as that number; any other value counts as no limit.

|`limit_status`
|<<limit-status,limit status>>
|`unverified`
|yes
|The count status and the paste view warning.

|`source`
|string
|none
|no
|A page URL or `screenshot:<file>`, empty for `unverified`.

|`options`
|list of strings
|none
|no
|`proposal set-field` accepts only these values for `choice` and `multichoice`, except on the `track` field.
The event's tracks replace the options of the `track` field when the event lists any.

|`audience`
|<<audience,audience>>
|`public`
|yes
|The relevance field, the review packet, and the paste view.

|`guidance`
|string
|none
|no
|`/cfp:draft` drafts each field from its guidance.
|===

[#field-kind]
=== Field kinds

[cols="1,4"]
|===
|Kind |Handling

|`text`
|Drafted from its guidance.

|`longtext`
|Drafted from its guidance.
A reviewer-only `longtext` field can be the <<relevance-field,relevance field>>.

|`choice`
|`/cfp:draft` asks you and never generates it.
When the field has `options`, `set-field` matches the value against them without regard to case and stores the option's spelling.

|`multichoice`
|When the field has `options`, `set-field` takes a comma-separated list, matches each part against them, and stores the parts comma-joined.

|`boolean`
|`/cfp:draft` asks you and never generates it.
`set-field` stores `Yes` for `yes`, `true`, `y`, `1` and `No` for `no`, `false`, `n`, `0`, and refuses anything else.

|`link`
|No kind-specific handling in `set-field`.

|`resources`
|No kind-specific handling in `set-field`.
`/cfp:draft` fills the field with id `resources` from your resources, whatever its kind.
|===

[#audience]
=== Audiences

[cols="1,4"]
|===
|Audience |Meaning

|`public`
|The default.

|`reviewer`
|Reviewer-only.
Candidates for the <<relevance-field,relevance field>>.

[#limit-status]
=== Limit statuses

[cols="1,4"]
|===
|Status |Meaning

|`page`
|From a page, with its URL in `source`.

|`screenshot`
|From a screenshot of the form, with `screenshot:<file>` in `source`.

|`unverified`
|Without a source.
A count within the limit gets the status `unverified` instead of `ok`, and the paste view warns that the live form may differ.
|===

The same values apply to `limit_status` on a field and to `bio_limit_status` on the profile.

[#relevance-field]
=== The relevance field

The relevance field is the field with id `benefits` when the form has one.
Otherwise it is the first field in form order with `audience: reviewer` and `kind: longtext` whose id is not `previously_presented` or `resources`.
With no such field the form has none, and `profile show` returns `relevance_field` as null.

The body has one section, `## Notes`.
In the `event write` JSON it goes into a `body` mapping or the key `notes`.

=== How an event merges onto a profile

* An override without an `id` is skipped.
* An override whose `id` matches an entry updates only the keys it sets.
* An override with an unknown `id` is added as a new entry, unless it has `remove: true`.
* A session type override with `remove: true` removes the entry.
Field overrides cannot remove a field.
* When the event lists `tracks`, they become the `options` of the `track` field.
* Every field `limit` is coerced, and so is `bio_limit`.
* The event's `submission_limit` replaces the profile's when it is set.
* `rubric`, `rules`, `rejection_reasons`, the bio keys, and `## Drafting guidance` come from the profile only.

== Calibration example

Default is what `example add` writes when its JSON leaves the key out.

[cols="2,2,2,5"]
|===
|Key |Type |Default |Used by

|`id`
|string
|the proposal id, else a slug of the title
|The file name.

|`profile`
|string
|the profile
|Set when the example is written.

|`event`
|string
|empty
|The review packet.

|`year`
|integer
|empty
|The review packet, and the sort order after `added`.

|`origin`
|string
|`manual`
|The review packet.

|string
|empty

The body sections are `## Title`, `## Abstract`, `## Benefits` (the text of the relevance field), and the optional `## Why it worked`.
The review packet carries the title, abstract, benefits, event, year, and origin of the newest examples, three by default.
`profile validate` does not read examples.

== What profile validate reports

`profile validate --profile <id> [--event <event>]` returns `valid` and a list of `problems`.
`valid` is true when the list is empty.

[cols="1,3"]
|===
|Part |Problems reported

|Profile file
|The profile does not exist.

|Fields
|A field without id, a duplicate id, an unknown `kind`, an unknown `limit_status`, an unknown `audience`, a `limit` that is not a positive integer or empty.

|Session types
|A session type without id, a duplicate id.

|Rules
|A rule without id, a duplicate id, an unknown `kind`, an unknown `severity`.

|Rubric
|No criteria while the profile is approved, a criterion without id, a duplicate criterion id.

|Bio
|An unknown `bio_limit_status`, a `bio_on_form` that is not `true` or `false`.

|Event (with `--event`)
|The event does not exist, a `profile` that names another profile, an empty `tracks` list, a session type override without id, a `remove: true` for a session type the profile does not have, a field override without id, a date key (`cfp_open`, `cfp_close`, `event_start`, `event_end`, `notification`) that is not an ISO date.
|===

`profile validate` does not check `name`, `platform`, `sources`, `params`, or any key the tables mark "no".
It also does not check the values inside a session type override or a field override, only their `id` (and `remove` for a session type override).
